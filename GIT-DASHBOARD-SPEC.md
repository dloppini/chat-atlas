Git dashboard specification

Local changes opens in All, with one row per path across staged, unstaged and untracked changes. New files use a green N badge and modified files use a yellow M badge. Status labels are available to assistive technology. A tracked-file preview compares with HEAD when available. The Unstaged, Staged and Untracked controls retain their specific comparisons.

Add a Git / Chats toggle beside + Chat in the existing header. Follow the selected project's linked folder, including repositories above that folder. Preserve conversation filters and selection when switching back. Git is read-only: show the repository root, current branch/detached HEAD, local and remote branches, a topology-preserving graph of the latest 100 commits across refs, and staged/unstaged/untracked paths. Refresh explicitly through the existing header control. Handle missing folders, non-repositories, missing Git, unborn branches, and stale asynchronous responses. Use existing theme tokens, keyboard focus, and responsive layout; long graphs scroll within their section. No checkout, staging, commit, network fetch, or destructive actions.

Evolution: replace the terminal graph with SVG commit lanes, parent connections and selectable history rows (hash, subject, author, date, refs). Add a lower file/diff inspector with Working tree / Staged / Untracked modes and selected-commit changes (first-parent comparison for merges). Render unified diffs with line numbers and added/deleted line styling. Validate commit hashes and exact file membership on the host; disable external diff/text conversion. Bound large text previews and reject symlink escapes. Preserve stale-response protection and project scoping. Keep this iteration read-only.

Visualization refinement: preserve the existing VS Code theme and read-only host API. Use SVG lanes with a persistent color along each first-parent path, distinct secondary-parent colors, and named ref badges on commit rows plus an expandable branch key. Compact only the Git-mode project header. Keep tree and diff heights independently editable (160-1200 pixels) in their existing toolbars and persist preferences through webview state. The diff retains unified patches, a scrollable file list, sticky filename and preview line counts; patch-body lines beginning with +++/--- are still additions/deletions after a hunk header. Verify merge topology, saved sizing, file/commit selection, and desktop/phone layouts in both themes.

Branch focus: add a labelled selector inside the Tree toolbar with All branches and local/remote refs, plus focus buttons in the existing expanded branch key. Request the selected ref directly from Git (latest 100 reachable commits, including merged ancestry), validating against exact repository refs rather than accepting revision expressions. Preserve the diff selection and independent heights, remember focus per project, correlate asynchronous requests, and provide All branches recovery if a saved branch disappears. This is a view filter only; no checkout or fetch. Cover branches beyond the all-refs preview limit and keyboard/theme/responsive controls.

Diff readability refinement: use an accessible branch icon in the existing Git toggle, preserving its pressed state and Chats return action. Default the independently editable diff height to 640px, preserving saved heights. Use a narrower file list with full-path tooltips, 13px diff text, compact line gutters, and no patch transport headers before text hunks. Retain metadata-only/binary previews, exact source text, line numbering, and all read-only selection behavior.

Fork-inspired workspace refinement: default to Fit window rather than legacy stored fixed pane heights. Keep custom sizes available behind the same toggle, and remember explicit layout preference. Compact commit rows to 32px with matching graph geometry. Share repository/branch disclosure and layout actions in one header. Give remaining desktop viewport height to the diff; provide Hide history and Wrap lines controls with keyboard/pressed states. Narrow screens retain a scrollable document and a tall diff. Preserve branch focus, file/commit selection, line numbers and exact patch content. Reference: https://git-fork.com/ (working directory view; visual inspiration only, no copied code).

Position and synchronization: explicitly identify checked-out branch/HEAD separately from inspected commits and filtered history. Show upstream ahead/behind counts from local refs (Fetch updates them), exact branch tips, and selected-branch unique commit counts relative to HEAD. Add Fetch (all configured remotes), Pull (clean tree, fast-forward only, no autostash), Push (explicit current branch to configured upstream, no force/tags). Validate action/project/trust/head at the host, serialize operations per repository, correlate completion across project changes, and refresh after success/failure. Missing remote/upstream, detached/unborn HEAD, dirty pull, divergence and auth failures must be explained. Test operations using disposable local bare remotes; do not operate on the user remote during verification.

Commit workflow: integrate Stage all / Unstage all with the comparison tabs and Stage file / Unstage file with the filename toolbar. Commit only the index, using a labelled multiline message field and a tonal Commit staged button with a staged-file count. Preserve drafts per project across refresh, errors and project switches; clear only a successfully submitted draft. Validate exact changed paths, HEAD/branch and index fingerprint on the host, retain working files when unstaging, handle unborn branches and renames, and preserve normal Git hooks. Reject empty messages, empty index and unresolved conflicts. Allow publishing a branch without an upstream to an explicitly selected remote using a non-force push.

Azure DevOps: recognize Azure Services HTTPS and SSH remotes without exposing embedded credentials. A Create PR action in the synchronization group opens Azure's native creation page with the pushed source branch selected; Azure supplies target selection, title, description, reviewers and final submission in the user's authenticated browser. Revalidate remote and branch on the host. Multiple remotes must be explicitly selectable; do not guess an organization or collect credentials. Explain unpublished branches and commits before opening. Follow Microsoft's documented sourceRef URL pattern: https://learn.microsoft.com/en-us/azure/devops/release-notes/2024/repos/sprint-246-update . Verify Git mutations in disposable repositories and the full UI matrix with fictional preview data; no real remote mutation during testing.

Large diff recovery: stream selected-file patch output, retaining at most 512 KiB while draining the remainder. Preserve UTF-8 boundaries, the existing truncation notice, complete file lists, and actual Git failures/timeouts. Working, staged and historical patches exceeding the former 4 MiB process buffer must return usable previews; selecting another small file must still return its full diff. Keep this fix local to patch reading and preserve mutation behavior.
